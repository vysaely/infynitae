## Bugs

### B1. Unfocused premap `set_fullscreen` steals active output and clears suppression
At `crates/infynitae-core/src/protocol.rs:1288-1297`, any toplevel in `AwaitingInitialCommit` or `before_first_map` has `set_fullscreen` recorded into `premap_fullscreen` without checking `focus.target()`. When that client commits its first buffer, `committed` (`protocol.rs:1441-1501`) converts the premap record into a live grant via `store_fullscreen` and (`protocol.rs:1602`) calls `take_output(id)`.
`take_output(id)` (`protocol.rs:732-753`) calls `self.clear_presentation_suppression(output)` (`L739`) and ends every prior fullscreen grant on `output` via `fullscreen_ended` (`L740-752`). Neither step checks whether `id` holds focus (`ADR-01` / A-8) or whether the user previously suppressed fullscreen on `output` to view another window (`w2`). Even with `FOCUS_ON_OPEN=user` refusing focus later in `backend-drm::new_mapped` (`crates/infynitae-backend-drm/src/lib.rs:1990-1993`), the new client has already raised (`protocol.rs:1600`), ended the prior fullscreen window, cleared suppression, and covered `output` while `w2` keeps keyboard focus.

### B2. `FocusNext`, `jump_to_window`, and `focus_cluster_slot` only inspect `pointer_output()`
All three navigation paths read only `self.pointer_output()`:
- `Apply KeyAction::FocusNext` (`crates/infynitae-core/src/entry.rs:744-753`)
- `jump_to_window` (`crates/infynitae-core/src/entry.rs:1275-1283`, called by `physical_input` `L278`, `focus_slot` `L1223`, `focus_direction` `L1264`)
- `focus_cluster_slot` (`crates/infynitae-core/src/entry.rs:1320-1328`)

Each checks `if let Some(output) = self.pointer_output()` and only suppresses or unsuppresses that single output:
1. **Cross-output over-suppression (`3A`):** With `w1` presenting on output `A` and pointer on `A`, `Super+Tab` to `w2` (which lives on output `B` and is already visible there) calls `suppress_presentation(A, out)` (`entry.rs:751`) and, when `focus_cycle_navigate` is set (`L756-759`), re-centers onto `w2`, kicking `w1` out of fullscreen even though `w2` was never hidden.
2. **Stuck suppression (`3B`):** With `A` suppressed while focus is on `w2` and pointer moved onto `B`, `Super+Tab` back to `w1` inspects `B` (not presenting `w1`), so `A` stays suppressed (`is_presentation_suppressed(A) == true`) and `focus_next` tries to pan `B` instead of restoring `w1` on `A`.
3. **Target remains hidden (`3C`):** With pointer on `B` (or `PointerState::NoOutput` before any mouse move), `jump_to_window` to `w3` hidden under `A`'s fullscreen leaves `A` presenting `w1` while moving keyboard focus to hidden `w3`.

### B3. Stale or hidden keyboard focus on layer surfaces
- **Hidden `OnDemand` layers retain focus (`4a`):** `layer_frame` (`crates/infynitae-core/src/layer.rs:340-369`) and `layer_hit` (`L373-384`) omit `Background`, `Bottom`, and non-`Exclusive` `Top` layers when `self.presentation(output).is_some() && !self.is_presentation_suppressed(output)`. However, starting or resuming presentation (`take_output`, `unsuppress_presentation`) never checks or calls `self.focus.layer_release(...)`. Because clicking an `OnDemand` `Top` bar sets `focus.layer = Some((bar, false))` while keeping `focus.target = Some(w)` (`FocusModel::layer_take`, `crates/infynitae-core/src/input/focus.rs:267-281`), `w` can still request fullscreen (`w` has `focus.target`), hiding `bar` from rendering, hit-testing, and frame callbacks while `focus.layer()` remains `Some(bar)`.
- **Exclusive -> OnDemand downgrade leaks exclusive lock (`4b`):** `layer_keyboard` (`crates/infynitae-core/src/layer.rs:633-647`) calls `layer_take(id, true)` when `keyboard == Exclusive` and `layer_release(id)` when `keyboard == None`, doing nothing for `OnDemand` or layer demotions (`Top`/`Overlay` -> `Bottom`). Downgrading an `Exclusive` `Top` panel to `OnDemand` leaves `focus.layer == Some((panel, true))`. `FocusModel::focus_to` (`crates/infynitae-core/src/input/focus.rs:138`) blocks all window focus moves when `self.layer_exclusive()` is true, so clicks on windows and `Super+Tab` stop working permanently.

### B4. `Effect::LayerKeyboardFocus` leaves active popup grab alive
`Effect::KeyboardFocus` in `crates/infynitae-wayland/src/outputs.rs:71-130` cleans up popups and takes/ungrabs `self.popup_grab` before calling `kb.set_focus`. `Effect::LayerKeyboardFocus` in `crates/infynitae-wayland/src/layers.rs:155-164` calls `kb.set_focus(self, Some(surface), serial)` directly without touching `self.popup_grab`, leaving an existing toplevel popup grab active while keyboard focus has moved to the layer surface (`audit_presentation_layer_keyboard_focus_does_not_dismiss_active_popup_grab`). Note: Smithay's internal `KeyboardHandle::set_focus` behavior on grabbed keyboards was not opened in `vendor/` (headless test confirms `keyboard_is_grabbed()` remains true and no `popup_done` is delivered).

### B5. `overview_toggle` suppresses its own `viewport_restore`
When closing Overview (`crates/infynitae-core/src/entry.rs:1498-1503`), `overview_toggle` checks whether `focus.target()` is presenting on `output`, calls `self.unsuppress_presentation(output, out)` at `L1501`, and then calls `self.viewport_restore(proof, out);` at `L1503`. `viewport_restore` (`entry.rs:1854-1858`) returns early without restoring whenever `presentation(output).is_some() && !is_presentation_suppressed(output)`, so the overview zoom level and camera history entry remain on the camera behind `F-PRESENT-1` until fullscreen later ends.

### B6. `show_chosen` suppresses unrelated outputs on two monitors
`show_chosen` (`crates/infynitae-core/src/entry.rs:1724-1735`, called by `show_opened`, `ShellCommand::Focus`, and `NavigateTo::Element`) evaluates `let hidden = self.hidden_by_presentation(id);` once globally (`L1726`) and then loops over all outputs calling `self.suppress_presentation(o, out)` whenever `Some(_) if hidden || pointer_on == Some(o)` (`L1731`). If `id` is observed only on output `A` (hidden by `A`'s presentation), output `B`'s independent fullscreen presentation is also suppressed.

### B7. `wlr_toplevel` `OutputEnter` covers all monitors; `edge-apps` unmaps everywhere
`wlr_toplevel_announce` (`crates/infynitae-wayland/src/wlr_toplevels.rs:126-135`) emits `Event::OutputEnter` for every `h` in `self.outputs`, and `wlr_toplevels.rs` never emits per-window `OutputEnter`/`OutputLeave` updates on membership changes or output hotplug. `live/edge-apps/src/wayland.rs:620-626` computes `os.fullscreen_under = self.toplevels.iter().any(|t| t.fullscreen && t.outputs.contains(&os.output))`. Consequently, one fullscreen or `fitted` window on monitor `A` causes `edge-apps` panels on monitor `B` to unmap when closed (`apply_mode`, `L169-175`).

### B8. `zwlr_foreign_toplevel_handle_v1.unset_minimized` skips provenance checks
In `crates/infynitae-wayland/src/wlr_toplevels.rs:214-230`, `Request::Activate` computes `validated` from whether the seat pointer or keyboard is currently on a surface of that client. In contrast, `Request::UnsetMinimized` (`L343-347`) hardcodes `state.core.activation_request(id, true)`. Because `protocol.rs:1242-1245` restores minimized windows on `validated && eligible` and calls `restore_minimized` -> `stage.raise(id)` (`L2343`) + `focus_to(id)` (`FocusModel::activation`, `input/focus.rs:304-322`), any foreign-toplevel client can un-minimize, raise, and focus any window at will.

### B9. `fitted` rendering culls occluded windows without updating hit-testing
When `crate::fitted::fills_the_view` succeeds, `convert.rs:787-793` (and screencopy `L1175-1179`) discards every other entry with `entries.retain(|e| e.element == window)`. Meanwhile `Core::hit_test` / `Core::route_pointer` (`crates/infynitae-core/src/lib.rs:2210-2276`) consults `ProjectionFrame::select` (`render.rs`), which honours `input_region` cutouts on `window` and falls through to elements behind it. A front `fitted` window with an empty or cutout `input_region` renders solid over the output while clicks/motion inside the cutout hit the invisible window underneath (`audit_presentation_fitted_occluded_window_not_drawn_but_still_hit_tested`).

### B10. `presentation_suppressed` leaks when fullscreen ends or moves without `take_output`
`clear_presentation_suppression(output)` (`crates/infynitae-core/src/lib.rs:828-840`) is called only inside `take_output` (`crates/infynitae-core/src/protocol.rs:739`). None of the fullscreen exit paths remove `output` from `presentation_suppressed`:
- `UnsetFullscreen` (`protocol.rs:1328-1339`, via `fullscreen_ended`)
- Unmap (`protocol.rs:1621`, `drop_fullscreen`)
- Destroy (`protocol.rs:1738`, `drop_fullscreen`)
- Output removal (`protocol.rs:833-836`, `fullscreen_output_removed`)
- Moving fullscreen from output `A` to `B` (`store_fullscreen` updates `f.output = B`, then `take_output` clears only `B`, leaving `A` suppressed)

### B11. `ShellCommand::Focus` gives keyboard focus to buried windows without raising them
`ShellCommand::Focus` (`crates/infynitae-core/src/entry.rs:2830-2837`) calls `show_chosen`, `focus.set_focus(Some(id))`, and `reconcile_constraints()`, omitting `self.raise_by_user(id)`. By contrast, `jump_to_window` (via `raise_and_focus`, `entry.rs:1293-1295`) and `focus_cluster_slot` (`L1329`) explicitly call `raise_by_user`. For an already-mapped window buried beneath another window, picking it via `ShellCommand::Focus` leaves the obscuring window on top in `render_list` and `hit_test` while keyboard focus moves to the buried window (`audit_presentation_shell_focus_does_not_raise_buried_window`).

### B12. Unconditional `stage.raise(id)` on map/remap (`INV-STAGE-5`) and `backend-drm` `bring_into_view` under `FOCUS_ON_OPEN=user`
- `protocol.rs:1600` calls `self.stage.raise(id)` on every initial map and every later remap (`unmap -> remap`), before any focus policy runs. Any unfocused background client can jump to top of z-order (even above a focused or `fitted` window) by unmapping and remapping without user input.
- In `crates/infynitae-backend-drm/src/lib.rs:1990-2030`, when `FOCUS_ON_OPEN=user` rejects focus (`focus_user_only && !user`), line `1991` calls `opened_without_focus(new_id)` and `continue`s out of the focus loop, leaving `hold[k] == false`. The camera/placement loop at `L2010-2030` skips only `if hold { continue; }` (`L2012`), so the unfocused app window still runs `bring_into_view` (relocating its anchor into the active viewport on top of the focused window, having already been raised at `protocol.rs:1600`), or `recenter_element` if `TELEPORT_ON_OPEN=true` instead of `"user"`. (Tested in Core for remap raise; `backend-drm` runtime path checked in code, not run on hardware.)

### B13. `overview_toggle` includes minimized windows in canvas overview fit
`overview_toggle` (`crates/infynitae-core/src/entry.rs:1429`) iterates `self.stage.mapped_elements()`, which checks `Lifecycle::Mapped` without filtering `is_minimized` (`crates/infynitae-core/src/stage.rs:204-210`). Minimized windows remain invisible in `render_list` and excluded from `focusable_elements()`, yet skew the overview center and zoom toward off-screen minimized anchors.

## Improvements

### I1. Client title/app_id `KEEP_ON_TOP` self-promotion (`protocol.rs:1208-1215`)
`toplevel_metadata` checks `named_on_top(id)` (`DEFAULT_KEEP_ON_TOP`, `protocol.rs:265`) and promotes `above = true` and snaps to `on_top_anchor` (`set_on_top`, `L2399-2407`) on any metadata commit unless `was_on_top`. A client can re-promote itself on title changes after the user unpins it or without user intent.

### I2. Suppressed fullscreen client moving to another output (`protocol.rs:544-550`, `694-725`)
`store_fullscreen` suppresses re-take (`repeat && is_presentation_suppressed(output)`) only when `(f.output == output)`. If `W` was presented+suppressed on `A` (e.g. via Overview) and sends `SetFullscreen { output: Some(B) }`, `repeat` is `false`, so `W` immediately takes `B` and clears suppression on `B`. Same if `pointer` moved to `B` or `fullscreen_output` picks `B`.

### I3. `wlr_toplevel_now` reports `Fullscreen` during suppression (`wlr_toplevels.rs:97-101`)
Taskbar and edge clients continue to see `State::Fullscreen` on `W` even while the user stepped aside (`is_presentation_suppressed(o)`), keeping `live/edge-apps` `fullscreen_under` unmap behavior active during normal windowed work or `Super+Tab`.

### I4. `hidden_by_presentation` indirection (`lib.rs:1040-1053`)
Checking `self.presenting() && self.membership.observing_outputs(id).next().is_none()` assumes `membership` is already synced and `self.outputs.iter()` includes `is_presentation_suppressed` through `membership` rather than checking `!self.is_presentation_suppressed(o.id)` directly.

### I5. Pointer hover and button/touch focus skip `reconcile_constraints()` (`entry.rs:347`, `364`, `2011`, `2665`, `2671`)
Focus moves from hover (`focus_follows_mouse`), pointer click, and touch do not immediately emit pointer constraint re-evaluations, unlike `set_focus` (`lib.rs:956`) and `apply_key_action`.

### I6. `leave_fullscreen` invalidation target (`entry.rs:1757`)
`leave_fullscreen` calls `invalidate_frame` on `self.pointer_output()` rather than `fs.output` (`presentation_membership` masks this by invalidating `fs.output`).

### I7. Active window state under `Exclusive` layer focus (`focus.rs:267-281`)
`layer_take(layer, true)` leaves `focus.target()` intact underneath the exclusive overlay; consider whether unfocused `set_fullscreen` / `Activated` should be withheld while `focus.layer().is_some()`.

### 5. Two-output behavior summary
- **`FocusNext` / `jump_to_window` / `focus_cluster_slot` (`B2`):** Only `pointer_output()` is inspected; target visibility/presentation on the other output is ignored, causing wrong-screen suppression (`A` suppressed for visible window on `B`), stuck suppression on `A` when pointer is on `B`, and un-suppressed `A` covering a jumped-to window while pointer is on `B`.
- **`show_chosen` (`B6`):** Uses global `hidden_by_presentation(id)` to suppress *every* presenting output, exiting fullscreen on `B` when choosing a window hidden only on `A`.
- **`wlr_toplevels` & `live/edge-apps` (`B7`):** `wlr_toplevel_announce` emits `OutputEnter` for all connected outputs regardless of camera visibility or presentation output, so fullscreen/`fitted` on `A` unmaps `edge-apps` panels on `B`.
- **`store_fullscreen` moving `A -> B` (`B10`, `I2`):** A suppressed fullscreen window moving from `A` to `B` leaves `A` in `presentation_suppressed` (`B10`) and bypasses `repeat` because `f.output != B` (`I2`).
- **`fullscreen_output` (`protocol.rs:544-550`):** `SetFullscreen { output: None }` picks `clock_output_of(id)` first, then `pointer_output()`; unlike `FocusNext`, `clock_output_of` works across two outputs, falling back to `pointer_output()` only when no output observes `id` (e.g., off-screen window).
