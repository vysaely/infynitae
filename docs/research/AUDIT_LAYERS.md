## Bugs

1. **Hidden `Layer::Top` steals or retains keyboard focus under active presentation (and lowering a focused layer keeps focus).**
   `layer_frame` (`crates/infynitae-core/src/layer.rs:343-348`) skips every layer except `Layer::Overlay` when `self.presentation(output).is_some() && !self.is_presentation_suppressed(output)`. `layer_keyboard` (`crates/infynitae-core/src/layer.rs:625-639`) does not check presentation visibility: a mapped `Layer::Top` surface asking for `KeyboardInteractivity::Exclusive` calls `focus.layer_take(id, true)` even when hidden. In addition, `keeps` (`crates/infynitae-core/src/layer.rs:631`) omits `r.layer().above_canvas()`, so lowering an `OnDemand` or newly non-`Exclusive` focused layer to `Layer::Bottom` keeps `self.focus.layer() == Some(id)`. Neither `take_output` (`crates/infynitae-core/src/protocol.rs:732-753`) nor `reconcile_presentation_change` (`crates/infynitae-core/src/lib.rs:843-862`) releases `focus.layer()` when presentation starts or unsuppresses, and `layer_in_use` (`crates/infynitae-wayland/src/layers.rs:83-94`) still treats that invisible keyboard holder as eligible for popup grabs.
   Proved by `layer::tests::audit_layers_hidden_top_layer_takes_keyboard_over_presentation`, `layer::tests::audit_layers_starting_presentation_keeps_focus_on_hidden_top_layer`, `layer::tests::audit_layers_lowering_focused_layer_below_canvas_keeps_focus`, and `t1_layer_shell::audit_layers_hidden_top_layer_steals_keyboard_on_presentation`.

2. **Configured layer unmapped before its first buffer never receives a remap configure.**
   `layer_committed` (`crates/infynitae-core/src/layer.rs:466-473`) computes `let remap = !mapped && !was_mapped && r.unmapped;` and updates `self.layers[i].unmapped = !mapped && (was_mapped || remap);`. If a client gets its initial `LayerConfigure` (`r.configured == Some(size)`), never maps a buffer (`was_mapped == false`), and commits `attach(None)` to unmap while a fullscreen/fitted window is active — as `OutputSurface::configure` -> `apply_mode` in `live/edge-apps/src/wayland.rs:170-187, 982-983` does when `fullscreen_under` is already `true` — `r.unmapped` stays `false`. When fullscreen ends, `apply_mode` sets `self.unmapped = false; self.layer.commit();` (`live/edge-apps/src/wayland.rs:188-191`) and waits in `!configured` (`193`) for a configure that Core never emits because `remap == false` and `relayout` skips layers whose `r.configured == Some(r.geometry.size)`.
   Proved by `layer::tests::audit_layers_unmap_before_first_buffer_never_gets_remap_configure` and `t1_layer_shell::audit_layers_unmap_before_first_buffer_never_configures_on_remap`.

3. **`wlr_toplevels` misses `sync_wlr_toplevels()` on acked fullscreen/unfullscreen commits and after `set_fitted_window` updates in render.**
   Two compositor paths set `self.wlr_toplevels.dirty = true` after `sync_wlr_toplevels()` has already run:
   - In `element_root_committed` (`crates/infynitae-wayland/src/handlers.rs:238-252`), `with_effects` calls `apply()` (`outputs.rs:325`, which runs `sync_wlr_toplevels()`) *before* line `251` sets `self.wlr_toplevels.dirty = true`. When a client acks `set_fullscreen` or `unset_fullscreen` and commits its buffer, `current_state().states` changes without triggering a `sync_wlr_toplevels()` call.
   - In `output_elements_marked` (`crates/infynitae-wayland/src/convert.rs:787-790`) and DRM lock/DPMS handling (`crates/infynitae-backend-drm/src/lib.rs:2273, 2334`), `set_fitted_window` sets `self.wlr_toplevels.dirty = true` (`crates/infynitae-wayland/src/fitted.rs:119`). `frame_tick` (`crates/infynitae-wayland/src/lib.rs:1121-1134`) and DRM render loops never call `sync_wlr_toplevels()`. So stopping fit via zoom-glide finish, buffer shrink/transparency change, DPMS off, or session lock leaves `edge-apps` thinking `fullscreen_under = true`.
   Proved by `t1_wlr_toplevels::audit_layers_commit_fullscreen_or_unfullscreen_does_not_sync_wlr_toplevels` and `t1_wlr_toplevels::audit_layers_fitted_window_clear_in_render_leaves_wlr_toplevels_unsynced`.

4. **`wlr_toplevels` reports `State::Fullscreen` while presentation is suppressed and announces `OutputEnter` for all outputs.**
   `wlr_toplevel_now` (`crates/infynitae-wayland/src/wlr_toplevels.rs:97-101`) checks `current.contains(xdg_toplevel::State::Fullscreen) || self.fitted_windows.values().any(|&w| w == id)` without checking `!self.core.is_presentation_suppressed(output)`. Meanwhile `wlr_toplevel_announce` (`129-135`) sends `OutputEnter` for every output in `self.outputs` regardless of which output the window presents or fits on, and never updates those outputs on hotplug. In `live/edge-apps/src/wayland.rs:620-628`, `fullscreen_under` checks `t.fullscreen && t.outputs.contains(&os.output)`, so suppressing presentation leaves `edge-apps` unmapped on the desktop and presenting on one output unmaps `edge-apps` on every other output too.
   Proved by `t1_wlr_toplevels::audit_layers_wlr_toplevel_reports_fullscreen_while_presentation_suppressed` and `t1_wlr_toplevels::audit_layers_wlr_toplevel_announces_output_enter_for_non_presenting_output`.

5. **`PopupLayer` deadlocks `frame_pending` when a notification arrives and expires under fullscreen presentation.**
   `complete_layer_frames` (`crates/infynitae-wayland/src/layers.rs:196-207`) only completes `wl_surface.frame()` callbacks for surfaces in `core.layer_frame(output)`, so `PopupLayer` (`Layer::Top`, `live/edge-apps/src/wayland.rs:1606`) gets no callback while presentation hides `Top`. When a notification slides in (`arriving == true`, `1696-1702`), `PopupLayer::render` requests `wl.frame()` and sets `self.frame_pending = true`. When the toast expires while presentation is still active, `PopupLayer::render` unmaps via `attach(None); commit();` (`1638-1648`) without clearing `self.frame_pending` or `self.again`. After leaving fullscreen, `PopupLayer` remains unmapped (`!r.mapped()`), so that pending callback is never completed, and every new notification hits `if self.frame_pending { self.again = true; return; }` (`1656-1659`).
   Compositor withholding checked in `layers.rs:196-207`; client state bug checked in `live/edge-apps/src/wayland.rs:1638-1709` (`edge-apps` runtime interaction not run live).

6. **`OutputSurface` lags arrival animation across unmap/remap round-trips and mis-tracks `frame_pending` on close and SHM exhaustion.**
   When `shell.open_panel` (`live/edge-apps/src/shell.rs:733`) opens while `os.unmapped == true`, wall-clock `opened_at` starts before `apply_mode` commits empty and waits for `configure` (`live/edge-apps/src/wayland.rs:188-192`). On `configure`, `apply_mode` -> `render_if_needed` renders frame 0 without advancing `shell.tick()` (`tick()` only runs inside `frame()` after frame 0's callback returns, `883-902`). Separately, closing sets `self.frame_pending = false` (`209`) without invalidating the live `wl_callback`, so reopening quickly lets the prior callback clear `frame_pending` early (`893`), and `clear_and_commit` when `acquire_slot()` returns `None` commits `wl.frame()` with `clear_pending = true` without setting `frame_pending = true` (`274-279`).
   Checked in code (`live/edge-apps/src/wayland.rs`, `live/edge-apps/src/shell.rs`).

7. **Locked session still completes layer frame callbacks every vblank (and `convert::render_output` draws layers while locked).**
   `WaylandState::frame_tick` (`crates/infynitae-wayland/src/lib.rs:1131-1132`) calls `self.complete_layer_frames(output, now)` unconditionally alongside `self.complete_lock_frames(output, now)`, even though DRM (`crates/infynitae-backend-drm/src/lib.rs:2337, 2817`) only renders `lock_elements` when locked. `convert::render_output` (`crates/infynitae-wayland/src/convert.rs:1290-1325`) calls `output_elements` directly instead of checking `lock_elements` first, so non-DRM callers render windows and layers while locked (`drm` does not call `convert::render_output`).
   Frame callback behavior proved by `t1_session_lock::audit_layers_locked_still_completes_layer_frame_callbacks`; `convert::render_output` checked in code.

8. **Initial layer configure omits `LayerPreferredScale` and `layers_output_reconfigured` skips scale updates for unmapped layers.**
   `layer_committed` (`crates/infynitae-core/src/layer.rs:475-477`) only emits `self.layer_scale(i)` on the `!was_mapped -> mapped` transition, after the client already drew and attached its first buffer (unlike `new_popup` at `crates/infynitae-wayland/src/layers.rs:242`). `layers_output_reconfigured` (`crates/infynitae-core/src/layer.rs:576-584`) reconfigures all layers on `output` at the new scale's logical size yet filters `layer_scale(i)` to `self.layers[i].mapped()`. A panel unmapped behind fullscreen receives a new logical size configure with no `preferred_scale`, then draws its remap frame at the old scale.
   Proved by `layer::tests::audit_layers_initial_configure_omits_preferred_scale` and `layer::tests::audit_layers_output_scale_change_skips_unmapped_layer`.

## Improvements

1. **Pass output scale (`view.scale`) instead of zoomed `view.k` to `layer_render_elements`.**
   Layer entries in `entries_of` (`crates/infynitae-core/src/layer.rs:247-263`) use `model.scale` (unzoomed output scale). `output_elements_marked` (`crates/infynitae-wayland/src/convert.rs:823, 842`) and `output_elements_screencopy` (`1187, 1204`) pass `view.k` (`zoom * scale`) to `layer_render_elements` (`538-566`), which constructs `WaylandSurfaceRenderElement::from_surface(..., 1.0)` and wraps it with `CanonicalRect::new(el, e.rect, k)` (`229-230`). Whenever `view.k != view.scale` (`camera.zoom != 1.0`), `own != rect` forces `remapped = true` with `cut = None`, which expands `damage_since` to the full surface (`360`) and clears `opaque_regions` (`371`) and `underlying_storage` (`411`). Note: rendered pixels and hit testing remain at the right unzoomed scale because `CanonicalRect::geometry` returns `self.rect` (`342`). Checked in code.

2. **Add withheld-frame fallback/kick for hidden layers and unify fitted/presentation layer visibility.**
   Unlike toplevels (`crates/infynitae-wayland/src/frames.rs:41-91`), layer surfaces whose `wl_surface.frame()` callbacks are withheld under presentation never get a ~1 Hz `frame_fallback` and get no immediate pre-vblank kick when presentation ends (`drop_fullscreen` / `unsuppress_presentation`). Separately, as noted in `docs/REVIEW-2026-11-11-window-states.md`, `fitted` windows only hide `edge-apps` via `wlr_toplevels` while other `Layer::Top` surfaces stay drawn and hittable over a fitted window (`convert.rs:787-795`). Checked in code.

3. **Handle output transform and live scale/mode reconfiguration for lock surfaces.**
   `lock_surface_size` (`crates/infynitae-wayland/src/lock.rs:420-429`) divides `mode.size` by `scale` without swapping axes for 90/270-degree transforms, and `output_changed` (`crates/infynitae-wayland/src/outputs.rs:550-569`) reconfigures layers without reconfiguring or rescaling active lock surfaces. Checked in code.

## Post-fullscreen panel lag and stall paths

When a user leaves fullscreen (either protocol presentation or a `fitted` window), a panel or notification strip in `live/edge-apps` can stall or lag on these paths:

1. **Missing `sync_wlr_toplevels()` after fullscreen leaves (`B3`).**
   - *Protocol fullscreen:* When a client commits its acked unfullscreen resize, `element_root_committed` runs `self.with_effects(...)` (which runs `sync_wlr_toplevels()` while `dirty` is still `false`), and only then sets `self.wlr_toplevels.dirty = true` at `handlers.rs:251`. `edge-apps` never receives `State::Fullscreen` removal until an unrelated focus/title/apply runs.
   - *Fitted window:* When a window stops filling the view (zoom-out glide stops, buffer shrinks/becomes translucent, lock, DPMS off), `output_elements_marked` (`convert.rs:789`) or `drm` (`lib.rs:2273, 2334`) sets `dirty = true` inside `set_fitted_window`, after `apply()` already ran; `frame_tick` never flushes `sync_wlr_toplevels()`.
   - *Suppressed presentation (`B4`):* Panning or `Super+Tab` away from fullscreen leaves `State::Fullscreen` on the handle indefinitely (`wlr_toplevels.rs:97-101`).

2. **Remap commit receives no `configure` if unmapped before first buffer (`B2`).**
   If `edge-apps` unmapped right after initial `configure` while a fullscreen/fitted window was already on that output (`was_mapped == false`), Core kept `r.unmapped = false` (`layer.rs:469`). After leaving fullscreen, `apply_mode` commits empty and waits for `configure` (`wayland.rs:188-193`), which Core never sends.

3. **Stale `LayerPreferredScale` on remap after a scale change under fullscreen (`B8`).**
   Because `layers_output_reconfigured` skips `!r.mapped()` (`layer.rs:579`), a remapping panel configures at the new logical dimensions with no new `preferred_scale` until after frame 1's buffer commits (`layer.rs:475-477`).

4. **Toast strip `PopupLayer` waits forever on a withheld frame callback (`B5`).**
   A notification arriving during fullscreen requests `wl.frame()` (`wayland.rs:1700-1701`), which the compositor withholds while `Layer::Top` is hidden (`layers.rs:196-207`). If the toast expires before leaving fullscreen, `PopupLayer` unmaps (`1641`) with `frame_pending = true`. Once fullscreen ends, `PopupLayer` is unmapped so the pending callback never fires, and every later notification stalls at line `1656`.

5. **Arrival timer starts before the configure/frame-callback round-trips (`B6`).**
   Opening an unmapped panel records `opened_at = Instant::now()` (`shell.rs:733`) before sending the remap `commit()`, waits for `configure` (`wayland.rs:188-191`), draws frame 0 at `open_ms = 0`, and waits for frame 0's `wl.frame()` completion (`893-898`) before `tick()` advances `open_ms` — by which point real time elapsed during the two round-trips skips the beginning of the slide-in curve.
