# INC-12 — independent review, round 1 (2026-10-16)

Status: **REVIEW. INC-12 stays EXPERIMENTAL:** not ratified; its exit needs INC-6
(`wp_viewporter`), a reviewed activation policy (OB-40) and runtime evidence (T3). Subject:
`experimental/inc-12-xwayland-satellite` (supervisor `0b1e6e9` … OB-9 test `60f374f`), reviewed
area by area; four defects found and fixed in `1399b9e`.

## Findings

| # | Area | Finding | Severity | Status |
|---|---|---|---|---|
| R1 | Focus-stealing prevention | A token counted as valid when its serial was no older than the keyboard's last focus `enter`. A client the user merely points at receives fresh **pointer** serials, so it could activate itself and take the keyboard focus. Reproduced with a second client: `a_hovered_client_cannot_take_the_focus` failed with the old rule (seeded control "a token from a client without the keyboard focus is validated" DETECTED) | high (focus theft) | fixed: a token is validated only if the client that created it holds the keyboard focus |
| R2 | Activation policy | Unvalidated requests were dropped silently; there was no way to choose a policy | medium | fixed: explicit `ActivationPolicy` (below) |
| R3 | X display access control | satellite started Xwayland without `-auth`; the abstract X socket has no permission checks, so any local user in the network namespace could connect and, e.g., read keystrokes of X11 clients | high (local) | fixed: private 0600 Xauthority (MIT-MAGIC-COOKIE-1, `/dev/urandom`), `-auth` to satellite, `XAUTHORITY` to the session's clients. T1 on the rehearsal: a client without the cookie is refused |
| R4 | Display ownership after a crash | a crash left lock + socket file; every later session skipped that number | low | fixed: a lock owned by our uid naming a dead process is reclaimed (with its socket file, if ours) |
| R5 | Environment inheritance | session clients and the satellite inherited the compositor's own `WAYLAND_SOCKET`, `XDG_ACTIVATION_TOKEN`, `DESKTOP_STARTUP_ID`, `XAUTHORITY` | low | fixed: removed (or replaced by the session's own) |
| R6 | Clipboard compatibility | no `wl_data_device_manager`: no clipboard for any client; satellite's X↔Wayland clipboard bridge is off; **GTK 4 refuses to start** ("The Wayland compositor does not provide one or more of the required interfaces", zenity, executed headless); `wl-copy` fails | **blocker for native apps** | open: design in `READINESS-2026-10-16/CLIPBOARD_AND_SHUTDOWN.md` (docs branch) |
| R7 | Session shutdown | no SIGTERM/SIGINT handling: a signal kills the compositor where it stands; the satellite panics on the dead connection, children survive, socket and lock stay | high (cleanup) | open: `proposal/a-signals` + design (dependency decision) |
| R8 | X11 menus need a focused toplevel | satellite parents override-redirect windows to the *last focused* toplevel; with nothing focused, no menu appears | low | documented; the run loops grant initial focus |
| R9 | Single satellite client | all X11 apps are one Wayland client: with an X11 app focused, another X11 app can obtain a validated token | inherent | documented (same as other satellite compositors) |

Areas reviewed with no defect: crash recovery (restart on the same display, backoff, Degraded),
on-demand start, socket ownership (both sockets held for the session; the abstract name cannot be
taken over), resource cleanup (sockets, lock, cookie removed on drop; satellite SIGTERM → SIGKILL,
reaped), popup placement and input (OB-9 T1: menu at (150, 200), click activates, Escape
dismisses), the `wp_viewporter` dependency (satellite 0.8.3 panics without it; INC-6 provides it).

## Proposed activation policy (OB-40 decides; implemented as the provisional default)

| Policy | Validated token (from the focused client, fresh serial, unused, < 10 s) | Any other request | When |
|---|---|---|---|
| **Strict (default)** | focus, if the window may take focus (INV-INPUT-8); else attention | attention | desktop default |
| AttentionOnly (opt-in) | attention | attention | users who never want programs to move focus |
| Permissive (opt-in) | focus | focus | trusted kiosks / debugging only |

Never in any policy: a camera move, an anchor change, focus to a window a presentation hides.
Configuration: `--activation-policy strict|attention-only|permissive` (Level D; a config file
later). Attention is a FocusModel set the shell will render; no client sees it.
